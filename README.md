# Alchemy — Backend многопользовательской карточной игры

Серверная часть многопользовательской пошаговой карточной игры, разработанная на базе **Spring Boot**.

Проект объединяет механику сбора ингредиентов, создания рецептов, управления игровыми ресурсами и взаимодействия нескольких игроков в режиме реального времени.

Основной акцент сделан на проектировании backend-архитектуры, разработке REST API, реализации авторизации, WebSocket-коммуникации и управлении сложным игровым состоянием.

## О проекте

Alchemy — многопользовательская игра, в которой участники собирают ингредиенты, открывают рецепты и создают новые продукты путём комбинирования доступных ресурсов.

Игроки ходят по очереди, выполняя действия с общим игровым столом. Ингредиенты могут использоваться в рецептах, а созданные продукты — становиться компонентами для более сложных рецептов.

Игра предусматривает настраиваемые лобби, приватные руки игроков, общие игровые ресурсы, управление очередностью ходов и обновление состояния игры в реальном времени.

## Основные возможности

### Авторизация и безопасность
- Авторизация на основе JWT.
- Механизм обновления токенов (Refresh Token).
- Проверка личности пользователя при обращении к защищённым endpoint-ам.
- Проверка участия пользователя в игре при подключении к WebSocket-подпискам.

### Управление лобби
- Создание и управление игровыми лобби.
- Управление участниками и лидером лобби.
- Настройка начальных параметров игры:
    - Количество карт на игровом столе.
    - Количество карт, выдаваемых каждому игроку.
- Изменять настройки до начала игры может только лидер лобби.
- Обновление состояния лобби в реальном времени.

### Управление игровым процессом
- Создание игровых сессий и инициализация партий.
- Управление колодой и отдельными картами.
- Начальная раздача карт игрокам.
- Размещение стартовых карт на общем столе.
- Управление очередностью ходов.
- Случайный выбор первого игрока.
- Автоматический добор карт в начале хода игрока.
- Сохранение состояния игры.

### Обмен данными в реальном времени

Для взаимодействия между сервером и клиентами используется **WebSocket + STOMP**.

Клиенты получают обновления о:
- Изменениях лобби.
- Состоянии игровой сессии.
- Очередности ходов.
- Состоянии общего игрового стола.

Приватная информация игроков, например карты в чужой руке, защищена от доступа других участников.

## Игровая механика

В основе игры лежит гибкая система карт и рецептов.

Каждая карта может содержать один или несколько ингредиентов, а также рецепт. Рецепты состоят минимум из двух компонентов. Компонентами могут выступать как отдельные ингредиенты, так и продукты, созданные с помощью других рецептов.

Такая модель позволяет создавать цепочки крафта произвольной глубины.

Основные игровые правила:
- Для создания рецептов используются активные ингредиенты на столе и ранее созданные продукты.
- Рецепт должен находиться в руке игрока.
- Использованные компоненты связываются с созданным продуктом.
- При использовании готового продукта в другом рецепте его исходные компоненты могут возвращаться на игровой стол.
- Игроки получают очки за выкладывание ингредиентов и создание продуктов.

## Архитектура проекта

Приложение построено на основе многослойной backend-архитектуры.

Основные доменные сущности:

- **User** — зарегистрированный игрок.
- **Lobby** — игровое лобби и настройки партии.
- **GameSession** — активная игровая сессия.
- **GameState** — текущее состояние игры.
- **Deck** — колода карт с сохранением порядка.
- **Card** — отдельная игровая карта, содержащая ингредиенты, рецепт, владельца и текущее местоположение.

Обмен игровыми событиями отделён от основной бизнес-логики с помощью событийной архитектуры.

Основные компоненты:
- `GameWebSocketService` — отправка игровых обновлений клиентам.
- `GameEventListener` — обработка игровых событий.
- `GameUpdatedEvent` — событие обновления состояния игры.
- `GameEventResponse` — DTO для WebSocket-сообщений.
- `GameSubscriptionInterceptor` — проверка доступа к игровым подпискам.

Игровые операции проектируются с учётом целостности состояния игры и защиты от некорректных действий.

## Запуск проекта локально

### Требования

Для запуска проекта необходимы:

- **JDK 25**
- **Apache Maven** (если Maven Wrapper отсутствует в репозитории)
- **PostgreSQL**
- **Git**

### 1. Клонирование репозитория

```bash
git clone https://github.com/Dzetik/AlchemyWebGame.git
cd <repository-name>
```

### 2. Настройка базы данных

Создайте базу данных PostgreSQL:

```sql
CREATE DATABASE alchemy;
```

Настройте подключение к базе данных в `src/main/resources/application.properties`:

```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/alchemy
spring.datasource.username=YOUR_USERNAME
spring.datasource.password=YOUR_PASSWORD
```

### 3. Настройка JWT

Для работы JWT-аутентификации необходимо задать переменную окружения `JWT_SECRET`.

**Linux / macOS:**
```bash
export JWT_SECRET=YOUR_SECRET_KEY
```

**Windows (PowerShell):**
```powershell
$env:JWT_SECRET="YOUR_SECRET_KEY"
```

Приложение получает секретный ключ из переменной окружения через `application.yml`:

```yaml
jwt:
  secret: ${JWT_SECRET}
```

### 4. Запуск приложения

Перейдите в корневую директорию проекта и выполните:

```bash
mvn spring-boot:run
```

Или с помощью Maven Wrapper:

**Linux / macOS:**
```bash
./mvnw spring-boot:run
```

**Windows:**
```bash
mvnw.cmd spring-boot:run
```

### 5. Проверка работы приложения

После успешного запуска сервер будет доступен по адресу:

```text
http://localhost:8080
```

WebSocket endpoint:

```text
ws://localhost:8080/ws
```

Документация REST API (Swagger UI):

```text
http://localhost:8080/swagger-ui/index.html
```

OpenAPI JSON:

```text
http://localhost:8080/v3/api-docs
```

### 6. Сборка проекта

Для сборки проекта и выполнения тестов:

```bash
mvn clean package
```

После успешной сборки исполняемый JAR-файл будет находиться в директории `target`:

```bash
java -jar target/demo-0.0.1-SNAPSHOT.jar
```
